# 实时通知功能使用说明

本文档旨在指导开发者如何使用本框架提供的实时通知功能。该功能基于 **服务器发送事件 (Server-Sent Events, SSE)** 实现，为需要从服务器向客户端单向推送数据的场景提供了一个高效、易用的解决方案。

## 核心组件

本功能主要由以下两个核心组件构成：

1.  **后端连接管理器 (`ClientConnectionHub`)**: 一个单例服务，负责在服务器端管理所有客户端的SSE连接、处理用户与连接的映射关系，并提供向指定用户或所有用户发送消息的API。
2.  **前端连接管理器 (`clientConnection`)**: 一个单例对象，负责在浏览器端建立和维护与服务器的SSE连接，处理自动重连、心跳维持，并提供注册和分发消息事件的接口。

---

## 后端使用指南 (`IClientConnectionHub`)

`IClientConnectionHub` 接口是后端与客户端连接交互的入口。它通过依赖注入在应用服务或控制器中使用。

### 接口定义

```csharp
// Letu.Basis/ClientConnection/IClientConnectionHub.cs

public interface IClientConnectionHub
{
    // 当SSE控制器建立连接时调用，注册一个新连接
    Task AddConnectionAsync(Guid userId, string connectionId, Func<string, object?, Task> handler, string? sessionId = null);

    // 当连接断开时调用，移除连接
    Task RemoveConnectionAsync(string connectionId);
    
    // 移除同一会话下的所有连接（例如，用户在其他地方登录）
    Task RemoveConnectionsBySessionAsync(Guid userId, string sessionId);

    // 向指定用户的所有连接发送消息
    Task SendMessageToUserAsync<T>(Guid userId, string type, T? payload);

    // 向所有已连接的用户广播消息
    Task SendMessageToAllAsync<T>(string type, T? payload);
}
```

### 使用示例

在你的应用服务中，注入 `IClientConnectionHub` 即可向客户端发送消息。

**场景：当一个任务完成后，通知创建该任务的用户。**

```csharp
// C#
using Letu.Basis.ClientConnection;
using System;
using System.Threading.Tasks;
using Volo.Abp.Application.Services;

public class MyTaskAppService : ApplicationService
{
    private readonly IClientConnectionHub _clientConnectionHub;

    public MyTaskAppService(IClientConnectionHub clientConnectionHub)
    {
        _clientConnectionHub = clientConnectionHub;
    }

    public async Task CompleteTaskAsync(Guid taskId, Guid taskCreatorId)
    {
        // ... 执行业务逻辑 ...

        // 向任务创建者发送通知
        var notificationPayload = new { TaskId = taskId, Message = "您的任务已完成！" };
        await _clientConnectionHub.SendMessageToUserAsync(
            taskCreatorId, 
            "task_completed", // 自定义事件类型
            notificationPayload
        );
    }
}
```

## 前端使用指南 (`clientConnection`)

前端的 `clientConnection` 对象在应用启动时会自动初始化，并负责处理所有底层的连接逻辑。开发者只需要注册关心事件的回调函数即可。

### 核心API

```typescript
// frontend/src/application/clientConnection.ts

// 注册消息处理器
registerMessageHandler(eventType: string, handler: (data: any) => void): void;

// 注销消息处理器
unregisterMessageHandler(eventType: string, handler: (data: any) => void): void;

// 获取当前连接状态 (0: CONNECTING, 1: OPEN, 2: CLOSED)
getConnectionState(): number;
```

### 使用示例

在你的React组件中，使用 `useEffect` 来注册和清理事件监听器。

**场景：在UI中显示任务完成的通知。**

```tsx
// a-react-component.tsx
import React, { useEffect } from 'react';
import { clientConnection } from '@/application/clientConnection';
import { antd } from 'antd'; // 假设使用Ant Design作为UI库

const TaskNotificationComponent: React.FC = () => {
    
    useEffect(() => {
        // 定义消息处理器
        const handleTaskCompleted = (data: { taskId: string; message: string }) => {
            console.log('收到任务完成通知:', data);
            antd.notification.success({
                message: '任务完成',
                description: `${data.message} (ID: ${data.taskId})`,
            });
        };

        // 注册事件监听
        clientConnection.registerMessageHandler('task_completed', handleTaskCompleted);

        // 组件卸载时，清理监听器，防止内存泄漏
        return () => {
            clientConnection.unregisterMessageHandler('task_completed', handleTaskCompleted);
        };
    }, []); // 空依赖数组确保只在组件挂载和卸载时执行

    return (
        <div>
            {/* 你的组件UI */}
        </div>
    );
};

export default TaskNotificationComponent;
```

## 默认事件类型

`clientConnection` 内部处理并分发一些默认事件，你可以监听它们：

*   `connected`: 当连接成功建立时触发。
*   `message`: 接收到未指定 `event` 类型的通用消息。
*   `notification`: 接收到 `event: notification` 的消息，这是框架内置的通知事件。
*   `error`: 当发生连接错误或达到最大重连次数时触发。
